1. Product Overview
This document defines the requirements for James Boutros's personal portfolio website. The site serves as a digital resume and project showcase targeted at university admissions contacts, recruiters, and professional connections. It must be visually distinctive, fast to load, and deployable on Vercel with a custom subdomain or personal domain.
The site must communicate James's identity as an aspiring electrical engineer entering the University of Waterloo Honours Electrical Engineering program, with a background in software development, community involvement, and academic achievement.
2. Goals and Non-Goals
2.1 Goals
Present James's education, experience, projects, skills, and accomplishments in a single polished web experience.
Make a strong first impression on recruiters and university contacts within the first 5 seconds of landing on the page.
Be fully responsive on mobile and desktop.
Deploy for free on Vercel with a clean subdomain such as jamesboutros.vercel.app.
Be easy to update as new projects, jobs, or achievements are added.
Include working contact links for email, phone, and LinkedIn.
2.2 Non-Goals
No backend or database required. This is a static site.
No user accounts, forms, or dynamic data beyond contact links.
No blog or content management system in v1.
No paid hosting or domain required for initial launch.

TinkerCAD — Fire Alarm
TinkerCAD, Arduino Uno, C++, MQ Gas Sensor, TMP Temperature Sensor
A dual-sensor fire detection system simulated in TinkerCAD and programmed in C++. Reads analog voltage from an MQ-series gas sensor on A0 and a TMP temperature sensor on A1. When gas concentration exceeds a threshold of 250 analog units or temperature exceeds 70 degrees Celsius, the system triggers a 523Hz buzzer tone and activates the corresponding alert LED. Demonstrates analog sensor interfacing, threshold-based control logic, and multi-hazard detection on a single Arduino Uno.
TinkerCAD — Two-Door Lock
TinkerCAD, Arduino Uno, C++, Servo Motor, 4x4 Keypad, I2C LCD, Buzzer
A PIN-based electronic door lock system built in TinkerCAD. Uses a 4x4 matrix keypad for input, a servo motor to physically actuate the lock mechanism between 50 and 110 degrees, an I2C LCD for real-time user feedback, and a buzzer for audio confirmation. The firmware implements a custom Password class with string comparison logic, append and reset methods, and operator overloading. Correct PIN triggers a single buzzer tone and servo unlock. Wrong PIN triggers a triple buzzer pattern and prompts retry. Demonstrates object-oriented C++, hardware interfacing, and real-world access control logic.
TinkerCAD — Traffic Light
TinkerCAD, Arduino Uno, C++, Interrupt-Driven I/O, LCD
A pedestrian-controlled traffic light system simulated in TinkerCAD. Uses a hardware interrupt on digital pin 2 to detect a pedestrian button press via an ISR (Interrupt Service Routine), immediately flagging a state change without blocking the main loop. On button press, the system cycles through a full pedestrian walk sequence: vehicles stop, pedestrians walk for 5 seconds, the green pedestrian light blinks as a warning, then traffic resumes through yellow and back to green. An LCD displays real-time state messages. Demonstrates interrupt-driven programming, non-blocking control flow, and multi-output state machine design.
TinkerCAD — Photoresistor
TinkerCAD, Arduino Uno, C++, Analog Sensing, LCD
An ambient light sensing system that reads analog voltage from a photoresistor on pin A0 and classifies light intensity into three zones. Values between 54 and 800 activate three red LEDs, 800 to 950 activates yellow LEDs, and 950 and above activates white LEDs. Each LED group is controlled through a reusable updateLEDs function. The LCD dynamically updates only when the light zone changes, avoiding unnecessary redraws. Demonstrates analog-to-digital conversion, threshold classification, grouped output control, and efficient display state management.

5. Design Requirements
5.1 Visual Style
Dark base theme: pure black or near-black background (#0a0a0a or #0d0d0d) with an extremely subtle texture overlay — either a faint grid of thin lines at 2-3% white opacity or a noise grain texture. Adds depth without distraction.
Primary accent: deep crimson red (#cc0000). Used sparingly and precisely: active nav indicator, CTA button fills, section rule lines, scroll progress bar, timeline line, skill hover states. No red glows, no red box shadows, no red text shadows anywhere.
White (#ffffff): used for primary headings and the hero name. Also used for the JB monogram intro and large faint watermark text at 2-3% opacity.
Secondary surface: dark glass morphism cards (#111111 at 90% opacity), extremely thin border (1px #333333), subtle inner top highlight (1px #ffffff at 4% opacity). No harsh borders, no colored glows.
Body text: #888888 at 14-15px with 1.8 line height. Section labels: 10px uppercase red with 4px letter spacing. Dates and tech tags: IBM Plex Mono 12px #555555.
Bold typographic hierarchy using a distinctive display font for headings paired with a clean monospace or sans-serif for body text.
Subtle background texture or animated particle/grid effect on the hero section.
Cards and sections use a slightly lighter dark surface with thin border lines, not harsh white boxes.
Professional enough to send to a recruiter, creative enough to stand out from a standard resume site.
5.2 Typography
Heading font: Bebas Neue or Oswald for bold impactful headings that match the red and black aesthetic.
Body font: IBM Plex Mono or Rajdhani for a technical sharp feel.
No Arial, Times New Roman, or soft rounded fonts on the live site.
5.3 Animations — Apple-Level Quality
Animations must feel exactly like Apple product pages: smooth, purposeful, physics-based, and tied to scroll position. Every interaction must have a response. Nothing is static. The benchmark is that the site feels alive without ever feeling gimmicky or overdone.
Hero text: each word or letter in the name animates in independently with a staggered spring physics reveal on page load. Not a simple fade, a weighted natural motion like characters dropping into place.
Hero background: animated geometric grid or particle field in deep red that subtly shifts and breathes. Reacts to mouse cursor position with a gentle parallax pull, exactly like Apple Vision Pro landing page behavior.
Scroll-linked section reveals: every section animates based on scroll progress using Framer Motion useScroll and useTransform. Elements do not just fade in, they translate upward with spring easing tied directly to how fast the user scrolls.
Sticky section pinning: key sections like Projects and Skills pin in place while inner content animates horizontally as the user scrolls, mimicking the Apple iPhone feature scroll where content evolves while the section stays fixed.
Project cards: on hover, the card lifts with a realistic box shadow bloom, a red glow pulses outward from the border, and the tech tags shift color. The card reacts to the exact cursor position within it using a 3D tilt transform (rotateX and rotateY based on mouse coordinates within the card bounds).
Hardware project cards: same 3D tilt and glow but with a slightly different accent treatment to visually distinguish them from software projects.
Experience timeline: the vertical red line literally draws itself downward as the user scrolls into the section using an SVG stroke-dashoffset animation tied to scroll progress. Each entry fades and slides in as the line reaches it.
Skills section: each skill pill animates in with a staggered spring pop, overshoots slightly and settles, exactly like iOS app icons bouncing into place. On hover each pill lights up with a red backglow.
Nav bar: on scroll past the hero, the nav transitions from transparent to a dark frosted glass background with a red bottom border using a smooth opacity and blur transition. Active section link has an animated red underline that slides between links as the user scrolls.
CTA buttons: at rest they have a slow pulsing red border animation. On hover the red fills in from left to right in a smooth sweep. On click there is a subtle scale press feedback.
Photo: subtle floating animation at rest, a slow continuous up and down drift with a red ring that glows and dims on a loop.
Scroll progress bar: 2px red line at the very top of the viewport that fills from left to right as the user scrolls the page.
Page transitions: if any internal navigation exists, sections cross-fade with a directional slide using Framer Motion AnimatePresence.
Cursor: custom cursor on desktop, a small red dot that follows the mouse with a spring lag and scales up slightly when hovering over interactive elements.
All animations must use Framer Motion with spring physics, not linear or ease-in-out. Performance must stay above 90 Lighthouse score. Use will-change and GPU compositing properties where needed to keep animations smooth.
5.4 Responsiveness
Fully responsive on mobile, tablet, and desktop.

5.5 Performance

8. Content Management
All site content must be stored in a single file at src/data/content.js (or content.ts if using TypeScript). This file is the only file that ever needs to be touched when adding new projects, jobs, skills, or achievements. The design, layout, and animation code must never need to be modified for a content update.
8.1 Required Data File Structure
src/data/content.js must export separate named arrays for each content type: projects, experience, education, skills, accomplishments, extracurriculars, and personal info.
Each array entry must be a plain JavaScript object with clearly named fields such as name, role, company, date, description, bullets, tech, and link.
The rest of the codebase must import from this file only. No content strings hardcoded anywhere else in the project.
8.2 Updating Content with AI Tools
Because all content lives in one file, updating the site with Cursor, Claude Code, or Claude.ai is trivial. Examples of valid update prompts:
Add a new project called X, built with React and Python, with this description and this GitHub link.
Add a new work experience entry for a summer internship at Y company from May to August 2027 with these three bullet points.
Add TypeScript to my Programming Languages skills.
Update my education to show I am now in second year at UWaterloo.
After any AI tool makes the change, push to GitHub. Vercel redeploys automatically within 30 seconds. No other steps required.

Whoever builds this site, whether a developer, Cursor, or Claude Code, must structure the project this way from day one.
